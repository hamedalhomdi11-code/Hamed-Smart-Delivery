# إعداد الحسابات وتسجيل دخول السائق — Hamed Smart Delivery

## ما ينفذه النظام

- تطبيق الإدارة يسجل دخوله إلى Worker ثم ينشئ هوية فعلية في Auth0 Database Connection ويربطها بسجل صلاحية في Cloudflare D1.
- تطبيق السائق يستخدم Auth0 Universal Login عبر اتصال قاعدة البيانات نفسه، ثم يرسل Access Token إلى `/v1/driver/session`.
- Worker يتحقق من توقيع JWT والجمهور والجهة المصدرة، ثم يتحقق من حالة حساب السائق وفترة الصلاحية من D1.
- كلمات مرور السائقين لا تحفظ في تطبيق الإدارة أو D1؛ Auth0 يدير بيانات الاعتماد.
- البريد الداخلي لكل حساب يستخدم نطاق `.invalid` المحجوز وغير القابل لاستقبال البريد. تسجيل الدخول يكون باسم المستخدم، وإعادة تعيين كلمة المرور تكون من الإدارة.

## إعداد Auth0 المطلوب مرة واحدة

1. افتح **Authentication → Database → Username-Password-Authentication**.
2. فعّل **Requires Username** ثم احفظ.
3. أبقِ حد اسم المستخدم من 1 إلى 15 حرفاً؛ التطبيق والخادم يطبقان الحد نفسه.
4. من تبويب **Applications** داخل الاتصال، فعّل تطبيق Native المسمى **My AppHamed Smart Delivery Android** واحفظ.
5. في إعدادات التطبيق Native، تأكد أن Allowed Callback URLs وAllowed Logout URLs تحتويان:
   `https://dev-sm0yv5i1vy4kqhz8.us.auth0.com/android/com.hamed.smartdelivery/callback`
6. لا تضف Client Secret إلى تطبيق Android. تسجيل الدخول يستخدم Authorization Code + PKCE.

## متطلبات Management API

تطبيق M2M **Hamed Smart Delivery Management** يجب أن يكون مخولاً على Auth0 Management API بالصلاحيات:
- `create:users`
- `read:users`
- `update:users`
- `delete:users`

الأسرار المطلوبة محفوظة في GitHub Actions Secrets ثم تُضبط كـ Cloudflare Worker Secrets؛ لا تضع قيمها في الملفات أو APK.

## طريقة التشغيل

1. افتح تطبيق الإدارة وسجّل الدخول باسم مستخدم الإدارة `Hamed` وكلمة المرور الأولية المحفوظة لديك.
2. أنشئ حساب سائق باسم مستخدم إنجليزي صغير من 1 إلى 15 حرفاً/رقماً، وكلمة مرور لا تقل عن 10 أحرف، وحدد مدة الصلاحية.
3. يجب أن تظهر نتيجة الإنشاء في قائمة السائقين. إنشاء الحساب ينشئ مستخدم Auth0 ثم يسجل ربطه في D1؛ إذا فشل ربط D1 يحاول Worker حذف مستخدم Auth0 لتجنب الحساب اليتيم.
4. افتح تطبيق السائق، اختر تسجيل الدخول، وأدخل اسم المستخدم وكلمة المرور اللذين أنشأتهما الإدارة.
5. بعد نجاح Auth0، يتحقق التطبيق من Worker. لا يفتح التطبيق إلا إذا كان الحساب موجوداً ونشطاً وداخل فترة الصلاحية.

## حدود التحقق

- نجاح بناء APK لا يثبت تسجيل الدخول الحقيقي.
- نجاح Worker health check يثبت اتصال D1، لكنه لا يثبت نجاح Auth0 user provisioning.
- يجب إجراء اختبار إنشاء حساب من تطبيق الإدارة ثم تسجيل الدخول به من تطبيق السائق على جهاز Android متصل بالإنترنت.
- التفويض دون اتصال لمدة 30 دقيقة ما زال غير منفذ؛ عند انقطاع الإنترنت لا ينبغي اعتبار الحساب مفوضاً للعمل الجديد.
- تحديد بداية ونهاية الصلاحية كتاريخين مستقلين ما زال يحتاج استكمالاً؛ واجهة الإنشاء الحالية تستخدم مدة محسوبة من وقت الإنشاء.
